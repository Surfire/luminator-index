# 第一版性能与效果验收

设计日期：2026-10-12。**以下是完整 v0.1 的验收目标，实测成绩单列。** 阶段 1 名称引擎与 CLI 已实现，本机百万条目、拼音、增量和资源结果见 [阶段 1 报告](phase1-results.md) 与 [2026-10-13 优化报告](filename-optimization.md)。获授权真实云盘目录的可枚举名称已在本机验证；云端完整覆盖、不可枚举占位目录、正文、语义、长名压力、后台全补扫并发及真实 UI 仍未验收。

目标是“按下快捷键后能可靠找到资料”，不是只测 C 匹配内核或向量余弦计算。首版基准机为已核对的 Apple M5 Max / 128 GB MacBook Pro；不把该机器的未来结果泛化到所有 Mac。

## 1. 数据和测量口径

| 数据 | 规模与要求 |
| --- | --- |
| 名称查询数据 | 100 万文件/目录条目；包含长路径、同名文件、中文、拼音、大小写、Unicode NFC/NFD；公布名称池字节数和分布 |
| 目录扫描数据 | 实际创建的合成文件树，100 万条目，含目录；不能用只在内存中生成的名称表验收扫描速度 |
| 内容数据 | 约 1 万份合成/可公开授权文档，形成约 10 万实际片段；包含 PDF、DOCX、TXT、MD 和中英混合；记录总字节/页数/token 数 |
| 正确性样例 | 中文中间子串、两字词、单字、数字编号、拼音、重命名、删除、连续修改、云占位和不支持文件 |
| 语义效果 | 先用开发查询调参；另备至少 50 条未用于调参的查询和人工标注可接受文件，其中中文不少于 30 条；增加至少 20 条库内无答案的查询 |

内容规模以实际片段数为准，不能固定每文档 10 段来凑数字。私人资料可以后续在本地补充体验，公开报告只放统计和匿名查询类别，不提交原文或私人路径。

Release / native arm64 构建；记录系统版本、提交、模型 revision/量化、线程设置、索引配置、磁盘、供电/低电量状态。关闭首次编译和模型下载的影响。避免后台大任务，但另测后台索引进行时的交互延迟，不只测空库或静止 daemon。

预热后，名称/全文至少 50 条不同查询，每条重复 20 次；报告 p50、p95、最大值、样本数和未命中情况。单字符和大量命中查询单列。UI 至少 30 条查询各重复 10 次，从最后一次有效输入到第一批结果实际显示计时，输入法组字时间不算引擎耗时。报告时不能删去超时样本。

冷启动分成 daemon 恢复、模型加载、首个语义请求三项。进程冷启动不等于磁盘缓存冷启动，不能清了进程就声称测了硬盘冷读；模型下载单独计时，不掺入日常查询。

## 2. 延迟与资源目标

| 指标 | 第一版目标 | 口径 |
| --- | --- | --- |
| 名称引擎查询 | p95 ≤ 20 ms | 100 万条目；不少于 3 ASCII 字符或 2 汉字；包含规范化、筛选、排序、Top-K 路径构建 |
| 名称高扇出查询 | p95 ≤ 80 ms | 单 ASCII 字符/单汉字；不得因截断候选而丢失本应在 Top-K 的结果 |
| Tinycast 名称首屏 | p95 ≤ 100 ms | 含合并窗口、socket、UI 提交；模型加载不影响；不直接沿用当前 120 ms FileSearch 防抖 |
| 全文引擎查询 | p95 ≤ 80 ms | 10 万片段；含中文原文验证、排序、聚合、片段构造 |
| Tinycast 全文展示 | p95 ≤ 180 ms | 含 UI 和 IPC；允许名称已经先显示 |
| 热模型语义完成 | p95 ≤ 300 ms | 10 万片段；从语义请求发出起，含 query embedding、向量检索、融合和 IPC；输入稳定等待另报 |
| Tinycast 语义补充 | p95 ≤ 500 ms | 从最后有效输入起，含约 150 ms 稳定等待、推理、融合和显示 |
| 模型进程冷启动 | ≤ 3 s | 已下载文本模型；单列真实耗时；期间名称/全文照常返回 |
| 名称首次全扫描 | ≤ 15 s | 100 万本地合成条目，从开始扫描到名称可查且编目已提交；不包含创建测试树，也不包含内容提取 |
| daemon 恢复名称可查 | ≤ 3 s | 100 万条已建索引；记录系统文件缓存状态 |
| 名称变更可见 | p95 ≤ 1 s | 从文件操作完成到查询反映变化，包含 FSEvents 与合并窗口 |
| 小文本内容更新 | p95 ≤ 15 s | 单个 ≤ 100 KB UTF-8 文件，队列空闲；从写入完成到全文及热模型语义更新；大 PDF 另报首批/全量时间 |
| 仅名称常驻内存 | ≤ 150 MiB | 100 万条标准名称集，含 Rust daemon、名称池及拼音键；公布分布与额外长名压力数据 |
| 内容/语义总增量内存 | ≤ 1 GiB | 10 万片段；daemon + helper 的物理内存变化，含模型、向量、工作缓冲；不只报告权重文件大小 |
| Tinycast 集成内存增量 | ≤ 50 MiB | 相同配置与查询下，相对原版进程基线，不把 Tinycast 原有内存计为引擎开销 |
| 无查询且无后台任务 | 模型 helper ≤ 30 s 退出，CPU 60 s 平均 < 1% 单核 | 名称/必要缓存可以常驻；持续索引时不宣称空闲 |

这些数值是有挑战的设计目标，特别是全扫描、SQLite 恢复及总内存；源码检查不能证明它们可达到。若测不到，记录实际瓶颈并调整实现或明确版本范围，不能不作说明就降低目标。

内存用 macOS physical footprint/系统可观察数据并记录各进程；Metal 和共享映射可能重复计数，不简单相加所有 RSS 当作真实总量。至少记录名称就绪、模型加载、持续内容索引、空闲释放四个状态的峰值和稳态值。公开索引磁盘体积、首次全文提取与编码总时长及每秒 token/片段数；当前不在没有文档大小基线时承诺“1 万文档几秒建完”。

Raycast UI 单独测量，报告宿主和桥接开销；同包在 Tinycast 的一次性 execFile 模式也单列。CLI 达标不能代替两个界面的实测。

## 3. 质量与正确性门槛

| 项目 | 通过条件 |
| --- | --- |
| 名称/路径 | 固定精确、子串、拼音、NFC/NFD 样例全部命中；已删除文件撤下；重命名后新路径有效 |
| 中文全文 | 固定中文中间词/双字/单字样例全部命中，并定位到真实原文；编号不能被语义结果挤掉 |
| 文件提取 | PDF 页号正确；DOCX 段落/表格样例可检索；不支持编码、加密、扫描 PDF 明确标记，不报成功 |
| 更新一致性 | 连续改写期间旧 generation 不得覆盖新内容；重命名内容不变可复用向量；内容变化必须撤下旧命中并更新 |
| 事件恢复 | daemon 停止期间的变化在恢复后补齐；事件丢失触发受影响范围重扫；暂停状态可见 |
| 语义找回 | 留出查询 Hit@5 ≥ 90%（至少一份人工认可文件进入前五），MRR@10 ≥ 0.80；公开中文子集结果 |
| 无答案查询 | 至少 20 条，显示语义结果的错误接受率 ≤ 10%；阈值仅在开发集调，不在留出集逐题调参 |
| 向量一致性 | 复用/改造 runtime 对相同 prompt 与量化参考向量 cosine ≥ 0.999；版本不一致不能混入同一索引 |
| 可选 ANN | 若引入，候选 recall@10 ≥ 95%，相对精确向量 Top-10；该指标不能代替人工语义相关性 |
| 开关 | 关闭全文/语义停止其任务与查询；关闭语义后无需模型仍可搜名称/全文；导入设置不能自动开启内容读取 |
| UI 选择 | 后到结果不抢选中项，过时 query 不覆盖新结果；中文组字、上下键、Enter、返回和窗口关闭行为正确 |
| 云目录 | 已下载文件能搜正文；仅名称元数据不标成内容就绪；未覆盖目录有说明，不自动下载 |

Hit@5 是“问题找回率”，不是所有相关文档的 recall；MRR@10 为首个可接受文件倒数排名平均值。人工先标注可接受答案再运行，不用模型给自己的结果打分。此处不测生成式回答准确率，因为第一版不生成回答。

## 4. 对照与交付证据

同一机器、同一可见目录、同一权限、同一名称集和 Top-K，与 Oil Find 的名称路径对照；内容/语义与固定版本 DigUp 对照。配置、索引是否预热、是否包含云占位、实际条目数和排序规则必须写出，不能拿范围更小的数据宣称胜出。

测量分为内核、daemon、CLI/IPC 和真实 UI 四段，最终以用户入口端到端为主。对照可暴露瓶颈，不要求为了“赢”上游而改变查询含义或降低召回。建立公开 benchmark 时先用合成/授权数据，并公开执行方法、版本和原始计时统计。

截至设计阶段已有的观察仅包括：

- Oil Find 上游 M1/M5 相关测试曾运行：23 项通过，0 失败；不是全部测试，也不是本引擎的结果。
- 对 DigUp 当前 FTS tokenizer 的合成 SQLite 复现表明：连续中文的中间词可能不命中。此复现只涉及词法检索，不涉及语义模型质量。
- 设计阶段尚无 Luminator 性能结果；现在已完成阶段 1 扫描、查询、IPC、增量与资源测量，详见单独报告。另已按用户指定范围测试私人目录的名称，原始记录仅保存在本机。推理、中文语义及 UI 仍未运行，没有下载模型或读取用户文件正文。

首版交付至少包括可运行安装产物、三种入口的使用说明、上述测量报告和已知覆盖边界；GitHub README 的性能表只能在这些测量完成后加入实测列。
