# 文件名阶段：查询、拼音与增量优化

日期：2026-10-13。测量实现提交：`e5b322e277d4e9bd45a76b7b4d95fce4cf0718f4`。本轮只优化文件名引擎与 CLI；没有接入正文、模型、Tinycast 或 Raycast。

在本机百万条目合成集上，普通查询 p95 从 14.53 ms 降到 **4.24 ms**，单文件变更可见 p95 从约 101–118 ms 降到 **20–34 ms**。名称阶段达到当前数据集的延迟、常驻内存与空闲 CPU 目标，可以进入限定目录的实际试用。GUI、完整云端覆盖及正文搜索仍需独立验收。

## 实际改动

- 名称匹配在大于等于 65,536 条目的索引上分成最多 4 段并行执行，保留全局文件 ID 与所有命中候选；小索引保持单线程。Oil Find vendor C 文件未修改。
- `--under` 按不同父目录缓存路径判断，避免为每个候选重复构造完整路径；精确文件和目录自身仍可命中。
- 默认 `auto` 模式优先字面精确名称，降低只匹配扩展名的排名；短拼音首字母参与排序。新增 `filename` 和 `pinyin` 模式，允许调用方明确检索意图。
- 通用 MIT 词组表优先于系统单字读音，修正常见上下文多音字，例如成都、银行、重复。最长匹配 2–5 字词组，未收录词回退到系统读音。全部 2,552 条上游词组一并引入，没有根据私人资料逐题补词；来源和许可证见 [第三方说明](../THIRD_PARTY_NOTICES.md)。
- socket 监听通过 `poll` 等待，查询到来可立即唤醒；FSEvents 合并延迟从 100 ms 调到 20 ms。
- 拼音键变化对应索引格式 **v2**。旧库被明确拒绝并保留，请指定新数据库路径重新扫描；不自动覆盖旧库。

## 测量方法

环境：Apple M5 Max / 128 GB，macOS 27.0.1 (26A434)，arm64 Release，Rust 1.96.0，接电。沿用上一轮实际创建的 1,000,000 条合成目录树：1,000 个目录、999,000 个空文件，其中 199,000 个中文名称、50,000 个 NFD 拉丁名称。不读正文；这是浅目录集，不代表深路径或超长名称压力。

目录与 SQLite 缓存已热，未清除操作系统缓存。每条查询预热一次，Top-K=20，普通 50 条 × 20 次、高命中 5 条 × 20 次、路径 1 条 × 20 次；p95 用最近秩法。引擎时间含规范化、匹配、筛选、排序和路径构造，排除进程启动与数据库恢复。IPC 数据使用 Python socket 客户端，包含连接、请求与回复解析。

保留三轮查询记录：首次优化结果、与编译/其他测试任务重叠的结果、其他任务结束后的最终结果。最终轮是在增量测试结束后运行，含已清理记录留下的少量 tombstone；实际可检索条目仍为百万。没有删除慢样本，也不把重叠任务的一轮称为受控后台压力测试。

建库比上一轮 3.17 s 更慢，仍在 15 s 目标内；词组处理增加了工作量，两个时间也受系统缓存与负载影响，不把差值全部归因于单个改动。内存是 `TASK_VM_INFO` physical footprint 与内核生命周期峰值，数组预留容量另列原始 JSON。新增首次样本的 220.95 ms 延迟保留，不擅自归因或排除。

与其他任务重叠的一轮：普通查询 p95 **8.70 ms** / max 68.70 ms，高命中 p95 **24.03 ms** / max 69.13 ms。首次优化轮普通查询 p95 4.93 ms。三个结果均公开；这说明负载会影响尾延迟，不能保证所有使用时刻都为 4 ms。

增量每次改动一个文件，目录内原有 999 个文件；新增、改名、大小修改、删除各 30 次。轮询包含在计时内，间隔 10 ms。百万目录全补扫期间的交互延迟仍未验收。`--under` 在 4 个 group 目录中各测试 `.pdf`、`报告`、`方案`、`a`、`qingquan`，逐条确认返回路径位于范围内。

## 真实目录与 Spotlight 对照的边界

已在用户明确指定的真实云盘目录执行名称覆盖、中文、全拼/首字母、在线增量、停止期间恢复和元数据前后核对。私人路径、文件名、查询集、索引及原始记录只保存在本机；本公开报告不附这些数据。可枚举云占位文件的名称不等于正文已经下载，不可枚举的占位目录仍会形成覆盖缺口。

提供 [Spotlight 对照脚本](../benchmarks/spotlight.py)：相同根目录、独立名称清单与至少 50 条中文字面查询，Luminator 使用 `--mode filename`，Spotlight 使用 `mdfind -onlyin` 与 `kMDItemFSName` 子串表达式。每条双方预热一次、各测至少 5 次，随机交替顺序；返回完整集合，不以不同 Top-K 比较。两者的进程启动、查询及输出耗时均计入，Python 的结果解析均不计入计时。

清单 JSON 格式为 `{"entries":[{"relative":"group/example.pdf","name":"example.pdf","kind":0}]}`；查询 JSON 是 `[{"query":"示例"}, ...]`。清单须来自同目录的独立名称元数据枚举，查询结果不可超过 10,000 条上限；脚本遇到上限会中止，避免把截断当成完整结果。实际运行记录保留在调用方指定的位置。

```sh
uv run --no-project python3 benchmarks/spotlight.py \
  --root /path/to/library --db /path/outside/library/names.sqlite \
  --inventory /private/local/inventory.json --queries /private/local/queries.json \
  --output /private/local/comparison.json
```

此对照是 **文件名 CLI 接口**，不是 Spotlight 图形界面、正文或全部系统功能。`mdfind` 的进程与查询接口开销也包含其中，不能把差值称为索引内核的纯速度差。

## 正确性与剩余限制

当前 `cargo test --locked` 通过 1 项单元测试与 5 项集成测试。新增覆盖：常见词组多音字、拼音模式、英文精确名称不被缩写挤掉、目录/精确文件范围过滤，以及 70,000 条目跨 4 段匹配时的全局 ID、末段最佳命中与确定性排序。既有 FSEvents、离线恢复、移动/删除/硬链接、Unicode、单写入者和分段请求测试继续通过。fmt、严格 clippy、Release 构建通过。

两字母缩写可能对应多个常用中文词，候选召回正确不等于目标一定排在前 20。可使用更长首字母、全拼、`--mode pinyin` 或 `--under`；不为提高私人测试分数而硬编码偏好。未收录的多音字、人名与上下文仍可能读错。

查询与事件更新仍顺序处理，大型补扫可阻塞查询；长期高频删除/改名的在线压缩、深路径/长名称压力、多个根目录、安装包、UI 以及全文/语义尚未实现或验收。当前成果是一套可试用的名称后端，暂不修改 Tinycast，不注册系统后台服务。
